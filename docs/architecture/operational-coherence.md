# Rig: Operational Coherence & Project Vision

## 1. The Core Transformation

Rig has evolved from a collection of AI-assisted developer scripts into a **governed operational substrate for cognition, orchestration, and software evolution**. 

Rig is no longer an "inference wrapper" or a "chatbot frontend"; it is a **replay-first operational runtime** where the workspace itself is the substrate for governed cognition.

---

## 2. Architectural Pillars

| Pillar | Description |
|--------|-------------|
| **Governed Execution** | Every action happens in a separate, isolated Git worktree under explicit governance. |
| **Replay-First Substrate** | System state is a deterministic reconstruction of immutable receipts and audit events. |
| **Operational Observability** | Truthful visualization via deterministic SVG instrumentation and projection-driven UI. |
| **Cognition Topology** | Execution routing, reasoning, and decisions are visualized as a navigable topology. |
| **Integration Soak** | Preproduction governance ensures stability through mandatory validation and human review. |
| **Operational UX** | A calm, ergonomic interface built on progressive disclosure and motion governance. |

---

## 3. The "Rig Doctrine"

This philosophy governs all development and architectural decisions:

1. **Replay-First**: If it can't be reconstructed deterministically from a trace, it isn't canonical.
2. **Truthful Observability**: The UI reflects the mechanical reality of the runtime (no fake "thinking").
3. **Progressive Disclosure**: Complexity is revealed only when operationally necessary.
4. **Calm Operational UX**: The interface must remain stable and readable under high system load.
5. **Governance Before Automation**: Policy and constraints must precede orchestration.
6. **Human Merge Authority**: AI is advisory; humans remain the final authority on all main-branch changes.
7. **Projection-Driven Rendering**: The frontend is a dumb renderer of backend-authored state; it has no hidden authority.
8. **Workspace as Substrate**: Orchestration, history, and governance live inside the workspace (`.rig/`).

---

## 4. Runtime & Platform Direction

### Orchestration vs. Monolith
Rig does not seek to be a monolithic inference engine. Instead, it **orchestrates execution substrates**. It provides the governance and observability layer for diverse backends:
- **MLX / oMLX** (macOS-native unified memory)
- **llama.cpp** (local execution)
- **OpenAI-compatible APIs** (external providers)

### Native macOS Integration
Rig embraces its platform-native roots:
- **Operational Shell**: Native SwiftUI.
- **Observability**: SVG + Projections over WebSockets.
- **Monitoring**: Native macOS menu bar integration for operational awareness.

---

## 5. Summary of Convergence

Rig achieves **Operational Coherence** by ensuring its subsystems are tightly coupled through doctrine, not just code:
- **Replay** enables **Topology**.
- **Topology** enables **Governance**.
- **Governance** enables **CI**.
- **CI** enables **Observability**.
- **Observability** enables **Onboarding**.

Rig is the **governed control plane** for the next generation of software evolution.
